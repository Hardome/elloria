## Где что хранить

| Каталог | Содержание |
| --- | --- |
| `rules/` | Постоянные требования и правила разработки |
| `guides/` | Инструкции по конкретным задачам |
| `decisions/` | Принятые решения, контекст и последствия |
| `reports/` | Результаты конкретных проверок с датой и ограничениями |
| `templates/` | Шаблоны [плана](templates/plan.md) и [решения](templates/decision.md) |
| `plans/` | Текущие планы, подпланы и отчёты приёмки |
| `tmp/plans/`, `tmp/tasks/` | Локальные черновики и материалы вне Git |

Создавайте каталоги по необходимости. Весь `docs/tmp/` исключён из Git.
Не помещайте в документацию секреты и данные заявок.

## Порядок работы

Создавайте план по шаблону, обновляйте статус и результаты проверок.
Связанные подпланы и отчёт приёмки храните рядом до приёмки всего цикла.
После приёмки перенесите полезные сведения в постоянную документацию, удалите план,
подпланы и отчёт приёмки, обновите ссылки. Архив не создавайте: история остаётся в Git.

Датированные отчёты описывают только выполненные проверки и их ограничения.
Требования ищите в `rules/`, принятые решения — в `decisions/`.

Пишите кратко и по-русски: правило или действие, ожидаемый результат.
Сохраняйте естественные фразы, ограничения и критерии проверки.
Разделяйте блоки пустыми строками, переносите длинные строки и используйте имена
файлов в `kebab-case`. Ссылайтесь на основной документ вместо повторения сведений.
При добавлении документа обновите карту и, если нужно, точечную ссылку в `AGENTS.md`.
