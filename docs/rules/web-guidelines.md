# Разработка Web

Web использует Next.js App Router, React, TypeScript и Tailwind CSS.
Сохраняйте существующую структуру:

| Каталог | Назначение |
| --- | --- |
| `web/src/app/` | Страницы, layout, metadata и стили |
| `web/src/app/(main)/Sections/` | Секции главной страницы |
| `web/src/components/` | Компоненты сценариев и повторяемые блоки |
| `web/src/components/ui/` | Общие элементы управления и типографика |
| `web/src/hooks/` | Повторяемые хуки |
| `web/src/lib/` | Общие утилиты и данные |
| `web/public/` | Изображения и видео |

Не создавайте дополнительные слои и файлы без конкретной необходимости.
Следуйте именованию соседних файлов. Импорты кода `src/` используют алиас `@/`.
Соблюдайте существующие правила ESLint, включая сортировку импортов.

## Маршруты и компоненты

Страницы и layout остаются серверными, пока им не нужны интерактивность, состояние
или браузерные API. Выделяйте такие части в клиентские компоненты с `'use client'`.
Не переносите серверную конфигурацию и секреты в клиентский код.
Для переходов используйте `next/link`, сохраняйте metadata и семантику заголовков.

Рабочий пример формы — [ContactDialog](../../web/src/components/ContactDialog/index.tsx).
Простые обработчики оставляйте рядом с разметкой; повторяемую или сложную логику
выносите по назначению. Не добавляйте библиотеку состояния или форм ради одного сценария.

## Запросы и формы

По умолчанию браузер отправляет `POST /api/contacts`, Next.js перенаправляет запрос в API.
Настройки адресов и момент их применения описаны в [конфигурации](../guides/api-configuration.md).
Не меняйте HTTP-формат только на стороне интерфейса: обновляйте контракт и сервер вместе.

Для формы сохраняйте подписи полей, маску телефона, согласие, состояния отправки,
успеха и ошибки. На время запроса блокируйте повторную отправку.
Проверка в браузере не заменяет серверную валидацию.
Проверяйте неуспешные HTTP-ответы, а не только сетевые исключения.

## UI и медиа

Используйте общие `Button`, `Input`, `Dialog` и компоненты типографики.
Оформление и доступность описаны в [правилах UI](design-system.md).
У изображений сохраняйте осмысленные подписи, у галерей — управление с клавиатуры.
Изменения проверяйте на узком и широком экране, включая длинный текст и прокрутку диалога.

## Проверки

Из корня репозитория выполните:

```sh
pnpm --filter @elloria/web run lint
pnpm --filter @elloria/web run typecheck
pnpm --filter @elloria/web run build
```

Проверьте изменённые сценарии по [ручному регрессу](../guides/regression.md).
Автоматического набора Web-тестов сейчас нет. При появлении сложной логики покрывайте
существенный пользовательский риск, не дублируйте реализацию тестами каждого компонента.
