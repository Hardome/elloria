# Оформление ELLORIA

Источники текущего оформления — [globals.css](../../web/src/app/styles/globals.css),
[корневой layout](../../web/src/app/layouts/root-layout.tsx) и [общие UI-компоненты](../../web/src/shared/ui).
Документ закрепляет существующий визуальный язык и правила его развития.

## Токены и типографика

Токены определены в `:root` и связаны с Tailwind через `@theme inline`.
Основной фон — `#18191A`, поверхность карточки — `#202122`, вторичный цвет — `#898D91`.
Для новых элементов подбирайте семантические классы `bg-background`, `bg-card`,
`text-foreground`, `text-muted-foreground`, `border-border`, `text-destructive`.
Цвет поверхности используйте вместе с подходящим цветом содержимого.

Не меняйте общие роли ради одного элемента. Если требуется новая роль,
задайте её по назначению в общих токенах и привяжите к Tailwind.
Отдельного переключения светлой и тёмной тем в текущем интерфейсе нет.

Шрифты Cormorant Garamond и Houschka Pro подключаются в layout.
Используйте варианты [типографики](../../web/src/shared/ui/typography.tsx)
для заголовков, основного текста и подписей вместо копирования наборов классов.
Сохраняйте иерархию `h1`–`h3` по смыслу страницы.

## Компоненты и состояния

Общие `Button`, `Input` и `Dialog` находятся в `web/src/shared/ui/`.
Подбирайте имеющийся вариант компонента, прежде чем добавлять новый.
Для объединения классов используйте `cn` из пакета `cn`.

Сохраняйте различимость `hover`, `focus-visible`, `disabled` и ошибки.
Клавиатурный фокус должен быть виден. Не передавайте ошибку только цветом:
добавляйте понятный текст. Кнопки с одной иконкой должны иметь доступное название,
поля — связанные подписи, диалоги — заголовок и описание.

## Адаптивность и взаимодействие

На мобильном экране содержимое не должно создавать горизонтальную прокрутку.
Диалоги ограничивайте высотой окна и сохраняйте доступ к полям, сообщениям и кнопкам
через прокрутку. Длинные подписи должны помещаться в доступную ширину.

Используйте поведение Radix Dialog для фокуса, закрытия и клавиатуры.
Не реализуйте конкурирующие обработчики без необходимости.
Форма должна явно показывать отправку, результат и возможность повторить запрос после ошибки.

После правок проверяйте клавиатуру, узкий экран, открытие и закрытие модальных окон,
состояния формы и отсутствие перекрытий. Сценарии — в [ручном регрессе](../guides/regression.md).
