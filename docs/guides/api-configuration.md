# Конфигурация API и подключение Web

Команды разработки выполняются из корня репозитория.
Создайте `api/.env` и `web/.env.local` по примерам, как описано в [README](../../README.md#локальный-запуск).
Не перезаписывайте существующие настройки и не сохраняйте реальные секреты в Git.

## API

Сервер загружает `.env` из рабочего каталога пакета `api`; переменные процесса
имеют приоритет. Проверка выполняется в [config/env.ts](../../api/src/config/env.ts).

| Переменная | Назначение и значение по умолчанию |
| --- | --- |
| `DATABASE_URL` | Обязательный URL PostgreSQL; пароль кодируется через URL encoding |
| `EXPORT_KEY` | Обязательный непустой ключ XLSX-выгрузки |
| `HOST`, `PORT` | `127.0.0.1:5000`; в контейнере `0.0.0.0:5000` |
| `NODE_ENV` | `development`, `test` или `production`; по умолчанию `development` |
| `CORS_ORIGIN` | Origins через запятую, без путей; по умолчанию `http://localhost:3000` |
| `LOG_LEVEL` | Уровень Pino, по умолчанию `info` |
| `TRUST_PROXY` | IP или CIDR доверенных прокси через запятую; по умолчанию пусто |
| `RATE_LIMIT_MAX` | Положительное число запросов с IP, по умолчанию `100` |
| `RATE_LIMIT_TIME_WINDOW` | Интервал вида `1 minute`, по умолчанию `1 minute` |
| `TEST_DATABASE_URL` | Подключение для создания временной тестовой БД; иначе используется `DATABASE_URL` |

При изменении `DATABASE_PORT` локального Compose обновите порт в `DATABASE_URL`.
Из процесса на хосте БД доступна по `127.0.0.1:55439`, внутри Compose — `database:5432`.

## Web и прокси

| Переменная | Назначение |
| --- | --- |
| `NEXT_PUBLIC_BACKEND_URL` | Адрес API для браузера; по умолчанию `/api` |
| `BACKEND_INTERNAL_URL` | Адрес API для rewrite Next.js; по умолчанию `http://127.0.0.1:5000` |

При стандартной настройке браузер вызывает `POST /api/contacts` на origin сайта,
а Next.js перенаправляет его в `POST /contacts` API.
Это правило задаётся в [next.config.ts](../../web/next.config.ts).
При прямом обращении браузера к другому origin API включите origin сайта в `CORS_ORIGIN`.

`NEXT_PUBLIC_*` доступно браузеру и встраивается при сборке; секреты там недопустимы.
Rewrite с `BACKEND_INTERNAL_URL` также формируется при сборке production-приложения.
После изменения этих значений пересоберите Web; для development перезапустите сервер.
В Dockerfile Web адрес API при сборке — `http://api:5000`.

## Выгрузка и безопасность

XLSX доступен через `GET /contacts/export?key=...`; отсутствующий или неверный ключ
даёт `401`. Через стандартный Web-прокси путь начинается с `/api/contacts/export`.
Ссылка с ключом даёт доступ к данным заявок: не публикуйте её и не вставляйте в отчёты.
Ключи выгрузки, заголовки авторизации и тела заявок скрыты из журналов API.

Cookie-сессий в приложении нет. CORS регулирует браузерные запросы и не заменяет
проверку ключа. В `TRUST_PROXY` указывайте только адреса доверенных прокси.
Health-маршруты исключены из rate limit. Swagger доступен в development
на `http://localhost:5000/documentation`, в production отключён.

## Проверка настройки

1. Запустите БД, примените миграции и запустите приложение по README.
2. Проверьте `GET /health/live` и `GET /health/ready`: оба должны вернуть `200`.
3. Отправьте тестовую заявку через форму и проверьте результат в изолированной тестовой среде.
4. Проверьте отказ выгрузки без ключа и XLSX с тестовым ключом.

Полный перечень ручных сценариев — в [регрессе](regression.md).
