# Проверки перед коммитом и push

Хуки управляются Lefthook и устанавливаются командой `pnpm install --frozen-lockfile`
из корня приложения. Повторная установка: `pnpm run prepare`.
В Docker без `.git` и при установке без dev-зависимостей установка хуков пропускается.

Перед коммитом lint-staged проверяет подготовленные файлы:

- API: Biome с автоисправлением; cspell для исходников, тестов, конфигураций TypeScript и README.
- Web: Biome для кода, JSON и CSS; затем ESLint для кода с автоисправлением,
  без допустимых предупреждений.

Применяются исключения из конфигураций Biome, cspell и ESLint.
Конфигурация cspell хранится в корне приложения: `cspell.config.yaml`.
Полная проверка орфографии API: `pnpm run spellcheck` из корня.
Исправления попадают в коммит; неподготовленные изменения в частично подготовленных
файлах lint-staged временно скрывает и восстанавливает после проверки.

Перед push проверяются типы API и Web, запускаются интеграционные тесты API.
Web-тестов в проекте нет. Для тестов API нужен локальный PostgreSQL с правом создавать
временные БД: настройте `api/.env` по примеру и выполните `pnpm run db:up`.
Можно задать `TEST_DATABASE_URL`, он имеет приоритет над `DATABASE_URL`.
Не используйте production-подключение. Ошибка проверки останавливает коммит или push.

Ручной запуск хуков из корня приложения:

```sh
pnpm exec lefthook run pre-commit
pnpm exec lefthook run pre-push --all-files
```

Полная проверка со сборкой остаётся командой `pnpm run check` и выполняется в CI.
