# Ручной регресс ELLORIA

Проверяйте изменённые сценарии и связанные с ними ошибки.
Полный список используйте перед выпуском. Чек-лист сам по себе не подтверждает прохождение.

## Подготовка и результат

Используйте локальную или выделенную тестовую среду с вымышленными именами и телефонами.
Запуск — по [README](../../README.md), проверка образов — по [инструкции контейнеров](local-containers.md).
Подготовьте тестовый ключ выгрузки. Не создавайте заявки на рабочем сайте ради регресса.

Зафиксируйте коммит, дату, способ запуска, браузер, размер экрана и результат каждого
проверенного сценария: пройден / ошибка / не проверен, с причиной ограничения.
Отчёт конкретного выпуска храните в `docs/reports/`; локальные логи — в `docs/tmp/tasks/`.
Не включайте в отчёт ключи, реальные контакты и ссылки с ключом выгрузки.

## Сайт и медиа

- [ ] Главная страница загружается без ошибок приложения и горизонтальной прокрутки
  на узком и широком экране.
- [ ] Навигация ведёт к нужным секциям; мобильное меню открывается, закрывается
  и позволяет перейти к выбранной секции.
- [ ] Карточки проектов показывают правильные названия и медиа; просмотр проекта
  открывается и закрывается, переключение слайдов работает.
- [ ] Медиагалерея показывает изображения и видео, переключение и закрытие работают.
- [ ] Страницы `/privacy` и `/consent` открываются, ссылки из формы ведут на них.
- [ ] При управлении клавиатурой виден фокус, элементы с иконками имеют понятные названия,
  диалоги закрываются по Escape и возвращают фокус инициатору.

## Форма заявки

- [ ] Форма открывается из общих действий и карточки проекта; источник заявки
  соответствует месту открытия, если оно передаёт `from`.
- [ ] Пустые имя и телефон, неполный номер и отсутствие согласия не позволяют
  отправить форму. Маска принимает ввод и вставку российского номера.
- [ ] При отправке виден процесс, поля и кнопка заблокированы от повторной отправки.
- [ ] Успешный запрос возвращает `201`, отображается подтверждение;
  при закрытии и повторном открытии форма очищена.
- [ ] При сетевой ошибке или ответе API с ошибкой показано сообщение;
  введённые данные сохранены и запрос можно повторить после восстановления API.

## API и выгрузка

- [ ] `POST /contacts` с корректным тестовым телом возвращает `201`, ID и дату сервера;
  без `from` источник в ответе равен `null`.
- [ ] Пустое или состоящее из пробелов имя и неверный телефон дают `400`
  с `code: invalid_request` и путями ошибочных полей.
- [ ] `GET /contacts/export` без ключа и с неверным ключом возвращает `401`.
- [ ] С правильным тестовым ключом скачивается XLSX с ID, именем, телефоном,
  источником и датой в часовом поясе Екатеринбурга. Проверьте созданную заявку.
- [ ] `GET /health` и `/health/live` возвращают `200`; `/health/ready` — `200`
  при готовой БД и `503` при недоступной БД. Проверку сбоя проводите только
  в изолированной среде, после неё восстановите подключение.

Через Web-прокси пути API имеют префикс `/api`.
Ограничения входных данных задаёт [OpenAPI](../../contracts/openapi.yaml).
После проверки удалите только созданные для неё записи в тестовой БД.
Любой не выполненный сценарий отмечайте явно.
