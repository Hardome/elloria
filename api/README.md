# ELLORIA API

Fastify, TypeScript, PostgreSQL 18.6, Drizzle ORM и Zod.
API разделён на инфраструктурные плагины, маршруты и репозитории предметных модулей.
Нужны Node.js 26.13.0 LTS и pnpm 12.16.1.

## Разработка

Из каталога `api`:

```sh
cp .env.example .env
pnpm install --frozen-lockfile
pnpm run codegen
pnpm run db:migrate
pnpm run dev
```

Перед запуском настройте `DATABASE_URL` и `EXPORT_KEY` в `.env`.
Пароль в URL PostgreSQL должен быть закодирован через URL encoding.
Сервер загружает `.env`, переменные процесса имеют приоритет.
Swagger UI в development доступен на `http://localhost:5000/documentation`.
В production документация отключена.
Запуск всего приложения описан в [корневом README](../README.md).

## Запуск в Docker

Из корня репозитория:

```sh
docker compose --profile app up -d --build
```

Compose ждёт PostgreSQL, применяет миграции и запускает API и web.
Сайт доступен на `http://localhost:3000`, API — на `http://localhost:5000`.
Реквизиты БД и ключ выгрузки в Compose предназначены только для локального запуска.
При обновлении существующего окружения после изменения схемы сначала выполните
`docker compose --profile app run --rm migrate`, затем обновите контейнеры командой выше.
Остановка: `docker compose --profile app down`.

PostgreSQL доступен на `127.0.0.1:55439`; порт можно изменить через `DATABASE_PORT`.
В этом случае обновите порт и в `DATABASE_URL` локального `.env`.
Для PostgreSQL 18 используется новый том `postgres18_data` с пустой БД.
Прежний том PostgreSQL 16 автоматически не подключается и не удаляется.

## Структура

- `src/app.ts` собирает приложение, `src/server.ts` запускает сервер и закрывает соединения при остановке.
- `src/plugins` содержит подключение БД, безопасность, документацию, health и обработку ошибок.
- `src/modules/contacts` содержит маршруты, репозиторий, преобразование ответа и XLSX-выгрузку.
- `src/db/schema` описывает таблицы; `src/db/migrations` содержит SQL, снимки и журнал Drizzle.
- `../contracts/openapi.yaml` — источник HTTP-контракта; `src/generated` создаётся командой `codegen`.
- `test` содержит общую настройку Vitest; тесты модуля расположены рядом с его кодом.

Рукописные импорты используют `#app/*` и `#test/*`. Генерируемые файлы вручную не меняются.
Маршруты отвечают за HTTP, репозиторий — за запросы к БД, выгрузка — за формирование XLSX.

## API

| Запрос                         | Результат                                              |
| ------------------------------ | ------------------------------------------------------ |
| `POST /contacts`               | `201` и созданная заявка                               |
| `GET /contacts/export?key=...` | XLSX; отсутствующий или неверный ключ возвращает `401` |
| `GET /health`                  | Состояние процесса, время и режим окружения            |
| `GET /health/live`             | Liveness без обращения к БД                            |
| `GET /health/ready`            | `200` при доступной БД и таблице заявок, иначе `503`   |

Пример запроса:

```json
{ "name": "Иван", "phone": "+7 (999) 123-45-67", "from": "Сайт" }
```

`name` и `phone` обязательны, длина каждого поля не превышает 255 символов.
Имя не может состоять из пробелов. Источник `from` необязателен.
Сервер назначает дату самостоятельно. Ответ содержит `id`, `name`, `phone`, `from`, `createdAt`.
Без источника `from` равен `null`; дата передаётся в ISO UTC.
Ошибки имеют формат `{ error, code, message, details? }`; ошибки валидации содержат пути полей.

В XLSX сохраняются ID, имя, телефон, источник и дата в часовом поясе Екатеринбурга.
Записи читаются порциями по 500, XLSX формируется в памяти.
Ключи выгрузки, заголовки авторизации и тела заявок не записываются в журналы API.
Ссылки с ключом предназначены для доверенного получателя; не публикуйте их.

## Конфигурация

| Переменная               | Значение                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------- |
| `DATABASE_URL`           | Обязательный URL PostgreSQL                                                         |
| `EXPORT_KEY`             | Обязательный непустой ключ выгрузки                                                 |
| `HOST`, `PORT`           | По умолчанию `127.0.0.1:5000`; в Docker `0.0.0.0:5000`                              |
| `CORS_ORIGIN`            | Origins через запятую, по умолчанию `http://localhost:3000`                         |
| `NODE_ENV`               | `development`, `test`, `production`                                                 |
| `LOG_LEVEL`              | Уровень Pino, по умолчанию `info`                                                   |
| `TRUST_PROXY`            | IP или CIDR доверенных прокси через запятую; пустое значение отключает доверие      |
| `RATE_LIMIT_MAX`         | Максимум запросов с одного IP, по умолчанию `100`                                   |
| `RATE_LIMIT_TIME_WINDOW` | Интервал, по умолчанию `1 minute`                                                   |
| `TEST_DATABASE_URL`      | Административное подключение для тестов; при отсутствии используется `DATABASE_URL` |

Cookie-сессии не используются. Запросы из командной строки разрешены без Origin.
Health-маршруты исключены из ограничения частоты запросов.

## Миграции

```sh
pnpm run db:generate
pnpm run db:migrate
pnpm run db:studio
```

После изменения схемы сгенерируйте миграцию и проверьте SQL до применения.
Не редактируйте применённые миграции. В production-образе используется `node dist/commands/migrate.js`.
Повторный запуск применяет только новые миграции.
Начальная миграция рассчитана на пустую БД. Старые данные Knex не переносятся.

## Проверки

```sh
pnpm run check
```

`check` запускает генерацию, Biome, cspell, Knip, проверку типов, Vitest и сборку.
`lint` не исправляет исходники; для исправлений есть `lint:fix`.
Доступны отдельные команды `typecheck`, `spellcheck`, `lint:knip`, `test`, `test:watch`, `build`.

Для тестов нужен PostgreSQL 18.6 и пользователь с правом создавать и удалять БД.
Vitest создаёт отдельную временную БД, применяет миграции и удаляет её после тестов.
Рабочая таблица заявок не очищается. Например, для выделенного тестового PostgreSQL:

```sh
docker run --name elloria-api-tests -d -p 127.0.0.1:55440:5432 -e POSTGRES_PASSWORD=elloria-tests-only -e POSTGRES_DB=elloria_tests_admin postgres:18.6-alpine
```

Задайте `TEST_DATABASE_URL=postgresql://postgres:elloria-tests-only@127.0.0.1:55440/elloria_tests_admin`
в окружении или локальном `.env`, затем запустите `check`.
